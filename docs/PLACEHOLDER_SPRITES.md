# Placeholder Sprite System

> **Status**: Placeholder — to be replaced with real pixel art

This document covers the procedural placeholder sprite generators and how they integrate with the engine.

---

## Overview

All placeholder sprites are generated by `@tool` EditorScripts that run inside the Godot editor. They produce:

1. **Horizontal spritesheet PNGs** — one PNG per animation (e.g., `idle_down.png`, `melee_windup_right.png`)
2. **Normal map PNGs** — matching `_normal.png` files for each color sheet (e.g., `idle_down_normal.png`), used for dynamic 2D lighting
3. **A SpriteFrames `.tres` resource** — embeds per-frame CanvasTextures that pair diffuse + normal textures and defines animation names, FPS, and loop settings

When real art is ready, either replace the PNGs in place or swap the `.tres` resource. No code changes needed.

## Sprite Pipeline Wizard

> **Primary tool** — use this for all new sprite work.

The Sprite Pipeline Wizard (`scenes/tools/sprite_pipeline.tscn`) is a 7-step tool that chains 3D capture, pixel art conversion, normal map generation, lighting preview, weapon anchor editing, and SpriteFrames export into a single workflow.

### How to run

1. Run `scenes/tools/sprite_pipeline.tscn` (F6 in Godot)
2. Follow the 7-step wizard

### Steps

| Step | Name | Description |
|------|------|-------------|
| 1 | Model & Animation | Select 3D model from `assets/3d_imports/`, pick animation, configure camera (elevation, zoom, target height). Presets auto-load per model. |
| 2 | Capture Preview | Auto-captures 3 directions (down, up, right) at 512x512 with overscan-based camera panning to prevent limb clipping. Also captures normal maps via a second render pass with a normal-output shader. |
| 3 | Pixel Art Settings | Configure output height, alpha threshold, dithering, palette, outline, denoising. Real-time preview. |
| 4 | Light Preview | Interactive lighting test. Drag a point light across the sprite to verify normal map quality. Includes presets: Torch, Sunlight, Moonlight, Spell. |
| 5 | Export | Processes all 3 directions with configured settings. Saves color sheets and `_normal.png` normal map files to `assets/sprites/final/{model_name}/`. |
| 6 | Weapon Anchors | (Optional) Place grip pixel (magenta #FF00AA) and direction pixel (cyan #00FFFF) on exported frames. |
| 7 | Apply to SpriteFrames | Load exported sheets into `resources/player_sprites.tres` as AtlasTexture regions with configurable FPS and loop. Automatically pairs diffuse and normal textures via CanvasTexture. |

### Presets

Camera and pixel art settings are saved per model to `assets/sprites/presets/{model_name}.json`. They auto-load when selecting a model.

### Normal Maps

The pipeline automatically generates normal maps from 3D models to enable dynamic 2D lighting on pixel art sprites.

#### Capture (Step 2)

During the Capture Preview step, the wizard performs two render passes per direction:

1. **Color pass** — standard 3D render producing the diffuse spritesheet
2. **Normal pass** — re-renders the scene with a normal-output shader that encodes surface normals as RGB color values

Both passes use the same camera settings and overscan parameters so the outputs are pixel-aligned.

#### Processing

Normal maps are downscaled from the 512x512 capture to the target pixel art resolution using **bilinear interpolation** (not nearest-neighbor). After downscaling:

- **Alpha threshold** is applied to match the color sheet silhouette
- **Re-normalization** ensures each pixel's RGB encodes a valid unit-length normal vector

Normal maps intentionally skip pixel art processing (no dithering, palette quantization, outlining, or denoising) to preserve smooth lighting gradients.

#### Light Preview (Step 4)

The Light Preview step provides interactive verification of normal map quality before export. Features:

- **Draggable point light** — tap/drag anywhere on the preview to reposition the light source
- **Presets** — quick-switch between Torch (warm, close range), Sunlight (white, directional), Moonlight (cool, dim), and Spell (colored, intense)
- Normal map artifacts (seams, flat regions, incorrect facing) are easy to spot under moving light

#### Export Output

The Export step (Step 5) writes both color and normal map files to `assets/sprites/final/{model_name}/`:

| File | Example | Description |
|------|---------|-------------|
| Color sheet | `idle_down.png` | Pixel art spritesheet (diffuse) |
| Normal sheet | `idle_down_normal.png` | Matching normal map spritesheet |

#### SpriteFrames Integration (Step 7)

The Apply to SpriteFrames step creates **CanvasTexture** resources that automatically pair each diffuse texture with its corresponding normal map. This enables Godot's 2D lighting system to apply per-pixel shading to the sprites.

To see lighting in-game, add `PointLight2D` or `DirectionalLight2D` nodes to your zone scenes. The pipeline produces the normal data; scene lighting is configured separately.

### Standalone Tools

Two standalone tools exist for specialized use:

| Tool | Scene | Use Case |
|------|-------|----------|
| Sprite Capture | `sprite_capture.tscn` | Simple one-off 3D captures (superseded by wizard) |
| Pixel Art Converter | `pixel_art_converter.tscn` | Process pre-captured spritesheets without re-capturing |

## Animation Naming Convention

All sprites follow the `{action}_{direction}` pattern. The action name is everything before the last underscore; the direction is the final token.

| Category | Actions | Directions | Loop |
|----------|---------|------------|------|
| Locomotion | `idle`, `walk`, `dash` | `down`, `up`, `right` | idle/walk: yes, dash: no |
| Legacy attack | `attack` | `down`, `up`, `right` | no |
| Melee | `melee_windup`, `melee_strike`, `thrust` | `down`, `up`, `right` | no |
| Casting | `cast`, `cast_release` | `down`, `up`, `right` | no |
| Throwing | `throw_windup`, `throw_release` | `down`, `up`, `right` | no |
| Aiming | `aim`, `aim_release` | `down`, `up`, `right` | no |
| Wolf-specific | `howl` | `down`, `up`, `right` | no |

Left-facing animations are handled by flipping the `right` sprites with `flip_h = true` at runtime — no separate left sprites exist.

### Fallback Chain

When the ability visual sequencer resolves an animation name, it tries these candidates in order:

1. `{action}_{direction}` — e.g., `melee_windup_down`
2. `{action}` — directionless fallback
3. `attack_{direction}` — legacy fallback
4. `idle_{direction}` — final fallback

### Weapon Anchor Pixel

A magenta pixel (`#FF00AA`) marks where the weapon sprite should be positioned on attack frames. Only present on actions that show a weapon:

- `attack` (frames 1-2), `melee_windup`, `melee_strike`, `thrust`, `aim`, `aim_release` — **have anchors**
- `cast`, `cast_release`, `throw_windup`, `throw_release` — **no anchors** (weapon hidden during casting/throwing)

The `CharacterVisuals` system scans for this pixel each frame to position the `WeaponSprite` layer.

## Weapon Placeholder Sprites

Weapons are generated procedurally by `PlaceholderWeaponSprites` (`scripts/combat/placeholder_weapon_sprites.gd`). Each weapon type provides a **texture set** — three directional textures (down, up, right) that match the character's facing direction. Left-facing uses the right texture with `flip_h = true`.

### Weapon Types

| Category | Factory Method | Down Size | Visual |
|----------|---------------|-----------|--------|
| `melee_1h` | `create_sword_set()` | 8×20 | Short blade + crossguard + handle |
| `melee_2h` | `create_greatsword_set()` | 10×26 | Longer blade, larger guard, fuller groove |
| `dagger` | `create_dagger_set()` | 6×14 | Short narrow blade |

### Weapon-Equipment Mapping

`PlaceholderWeaponSprites.create_set_for_category(weapon_category)` maps `EquipmentData.weapon_category` to the correct texture set.

### Weapon Visibility Rules

Weapons are **hidden by default** during idle, walk, and all non-combat states. They only appear when an ability template explicitly includes a `WEAPON_VISIBILITY(true)` phase.

For melee attacks:
1. Weapon **shows** during windup (sword raised)
2. Weapon **hides** before strike (replaced by slash effect VFX)
3. Weapon **stays hidden** through recovery and idle

### Replacing with Real Art

Replace the procedural textures by providing your own texture sets. Pass a dictionary with "down", "up", "right" keys to `CharacterVisuals.set_weapon_texture_set()`. Or replace the factory methods in `PlaceholderWeaponSprites`.

## Effect Placeholder Sprites

Combat effects are generated by `PlaceholderEffectSprites` (`scripts/combat/placeholder_effect_sprites.gd`). Each effect is a self-contained Node2D with a procedural texture and tween-based animation that auto-removes after its lifetime.

### Melee Effects

| Effect ID | Used By | Size | Lifetime | Description |
|-----------|---------|------|----------|-------------|
| `slash_arc` | melee_single, melee_combo | 24×24 | 0.15s | White-gray arc sweep |
| `slash_arc_wide` | melee_combo hits 2-3 | 28×28 | 0.18s | Wider arc for combo hits |
| `thrust_line` | thrust attacks | 16×4 / 4×16 | 0.12s | Narrow directional stab line |
| `impact_spark` | damage events | 12×12 | 0.10s | Star/cross flash (non-directional) |

### How Effects Work

1. `AbilityVisualPlayer` emits `effect_event(effect_id)` during an `EFFECT` phase.
2. `CharacterVisuals._on_effect_event()` calls `PlaceholderEffectSprites.create_effect(effect_id, direction)`.
3. The factory returns a Node2D with a Sprite2D child and a ready-connected tween.
4. `CharacterVisuals.spawn_effect()` adds it to `EffectAnchor`.
5. The tween animates scale + fade, then `queue_free()` removes the node.

### Replacing with Real Art

Replace effects by modifying `PlaceholderEffectSprites.create_effect()` to return your own VFX nodes (particle systems, AnimatedSprite2D, etc.). The Node2D contract is simple: it gets added as a child of EffectAnchor and should handle its own lifecycle.

### Player Integration

## Starved Wolf Sprites

- **Size**: 32×32 per frame
- **Character**: Gaunt quadruped wolf with matted dark fur, visible ribs, red eyes
- **Palette**: Dark furs (`#1A1A22`, `#2A2A3A`), blood-red eyes (`#AA2233`), gray ribs/fangs
- **Animations**:
  - idle (4f @ 6fps) — subtle breathing
  - walk (6f @ 10fps) — trotting with leg alternation
  - attack (5f @ 12fps) — crouch, launch, airborne with open maw, strike, land
  - howl (6f @ 8fps) — head raises, blood-red aura radiates outward

### Wolf Integration

Wolves are created dynamically via `DatabaseLoader.create_enemy("ene_starved_wolf", level)`. The `_load_enemy_sprite_frames()` function in `autoloads/database_loader.gd` auto-loads the SpriteFrames by convention:

```
enemy_id:  "ene_starved_wolf"
short_id:  "starved_wolf"        (strips "ene_" prefix)
path:      "res://resources/enemies/starved_wolf_sprites.tres"
```

No scene edits or manual wiring required. `BaseCharacter._setup_sprite()` assigns the resource and handles animation playback.

## Adding a New Enemy's Placeholder Sprites

1. **Copy** `scripts/tools/generate_wolf_sprites.gd` as a starting template
2. **Update** constants: `SPRITE_DIR`, `SPRITEFRAMES_PATH`, palette colors, `ANIM_DEFS`
3. **Implement** the drawing functions for the new enemy's silhouette
4. **Run** the generator in the editor (Script > Run)
5. **Verify**: `DatabaseLoader.create_enemy("ene_<name>", level)` will auto-load `resources/enemies/<name>_sprites.tres`

The naming convention does all the wiring — no code changes needed in DatabaseLoader.

## Replacing with Real Art

When real pixel art is ready:

- **Option A — Drop-in replace**: Replace the PNG files (both color and `_normal.png`) in the same directories, keeping filenames and frame counts identical. The `.tres` resource and all code references remain unchanged.
- **Option B — New SpriteFrames**: Create a new `.tres` resource with real art (and matching normal maps if using lighting) and place it at the same path. The convention-based loader picks it up automatically.
- **Option C — Delete generators**: Once real art is in place, the generator scripts in `scripts/tools/` can be removed. They have no runtime dependencies.

> **Note on normal maps**: If your real art includes hand-painted or baked normal maps, name them with the `_normal.png` suffix alongside the color sheets. The SpriteFrames builder will pair them automatically.
